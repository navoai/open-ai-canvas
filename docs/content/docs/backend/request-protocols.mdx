# 请求协议管理

管理员可从「模型与渠道 → 请求协议」或「插件管理 → 请求协议工作台」维护声明式供应商接口规则。API 网站负责地址，Key 分组负责凭据、代理和并发，渠道模型负责能力、版本选择与价格；请求协议负责创建、查询、下载接口以及参数和响应映射。

## 统一插件发行边界

请求协议管理复用影策现有的声明式 `.yingce-plugin` 插件运行时，不新增第二套执行引擎、平行安装系统或数据库表：

- 新建或更新协议时，服务端将声明式 `manifest.json` 打包为标准 `.yingce-plugin`（`runtime.backend = "declarative"`），通过原生的 `pluginRuntime` 安装与 `requestReleases` 归档流程写入 `plugin_registry.json`；未显式声明 `permissions` 时默认补齐 `["generation.run", "media.read"]`，与官方协议插件包保持一致。
- 同一协议保持稳定的插件 ID 与 Provider ID，升级时仅递增 SemVer 主版本号（`1.0.0` → `2.0.0`），旧包按 SHA-256 摘要保留在插件归档中，不覆写历史包。
- 内置或官方协议插件在列表中只读展示，可查看全部归档版本或复制为新的自定义协议；无法覆盖内置插件、非声明式插件或其他插件已占用的 Provider ID。
- 停用、启用、下载包体与卸载（标记 `withdrawn` 同时保留历史归档）均与「插件管理」保持一致。

## 配置与离线校验

- 基本表单支持 Bearer、自定义请求头、查询参数和无需鉴权；API Key 由运行时从渠道注入，禁止在协议字段默认值、请求头或查询参数中写入凭据。
- 「接口与参数」配置相对渠道 Base URL 的创建、查询与可选独立下载路径；查询和下载支持 `{{taskId}}` 占位符。复杂对象、条件、固定值、签名、上传前置步骤等可在高级 JSON 中编辑。
- 「校验与发布」通过生产声明式适配器构造请求并解析示例响应，不访问真实供应商、不读取渠道密钥、不创建任务。示例响应表示成功但未解析出作品内容或地址（且未配置独立下载接口）时会拒绝。

## 示例：Grsai Wan 3.0 视频

1. 在「插件管理」搜索 `grsai-wan-video`。已有该发行版可直接绑定；没有则用「上传插件」安装 `plugin-packages/grsai-wan-video.yingce-plugin`。上游模型 ID 填 **`wan-3.0`**，不要选百炼 Wan 或 OpenAI 视频协议。
2. 在「渠道管理」导入配套的 `plugin-packages/grsai-wan-video/config/grsai-wan-video-channel.json`，确认回执为新建一个渠道、保存一个模型、无错误。模板使用全球节点 `https://grsaiapi.com`，没有 Key，渠道、模型和三个价格档都停用。**同名导入会合并**，不要覆盖正在使用的渠道。若使用国内节点，单独配置 `https://grsai.dakka.com.cn`；在途任务要在原节点回查。
3. 在渠道填写 Grsai API Key，按账号实际价格配置 480p、720p、1080p 的按秒价格档，然后按需启用。模板开启「参考视频计费」：上游按 **（输出秒数 + 输入参考视频秒数）× 输出分辨率秒价** 计费。模板未填单价不等于免费；返回的 `usage.credits` 不是 token。参见[参考视频计费](/docs/backend/video-token-billing)。
4. 首次联调可用 2 秒、480p、16:9、不带素材的文生任务（**会产生上游费用**）。宿主以 `replyType: async` 提交一次，保存回执 ID，以 `GET /v1/api/result?id=…` 回查。应验证作品在资源库中可播放，不只看「任务已创建」。`violation` 和 `failed` 都终止。最终结果产出后任务可查 2 小时，这不是媒体 URL 的有效期。需要下线时先停用渠道、处理在途任务，再停用插件。

**素材边界。** 首帧、首尾帧与普通参考图是不同输入；本版不开放仅尾帧、关键帧混用参考素材。参考图最多 10 张，参考视频最多 5 个 MP4、合计不超过 15 秒。参考音频最多 5 段，上游未说明 15 秒限制是否合计；本插件检查单段时长，多段请用实际账号确认。音视频参考须有时长信息。接口定义见 [Grsai 生成文档](https://qmy27nhsd9.apifox.cn/531060669e0) 与[结果查询文档](https://qmy27nhsd9.apifox.cn/452409577e0)。

## 声明式文本策略顺序

文本 Provider 可在高级 JSON 中声明 `hostTextPolicy: "before_mapping"`：宿主先解析本次流式开关、输出上限和思考策略，再交给插件执行型号差异映射。插件负责最终请求体，宿主不再在映射后追加思考字段或 `stream_options`，也不自动删除插件声明的用量字段并重发。

- Create 从 `request.extra` 接收宿主策略，Agent 从 `request.extra.agent` 的对应线格式请求接收；插件须明确映射这些字段。
- 该模式下 Create 与 Agent 共用 `requestBindings` 和 `validations`，非法型号或参数不能通过 Agent 绕过。
- 只允许文本单能力 Provider 使用此值；未知值拒绝加载。省略字段的既有插件保留原策略顺序和 Agent 校验合同。
- SenseNova 文本协议使用此模式，避免 Kimi 输出预算字段被改回 `max_tokens`，或向 GLM 注入未声明的 `stream_options`。

## 发布、并发保护与模型绑定

- 发布前必须对当前配置和示例完成校验。请求携带当前发行包的 `expectedSha256`（首次发布为空）；并发修改返回 HTTP 409，避免覆盖其他管理员的新版本。
- 发布新版本不会自动改写已锁版的渠道模型。管理员可在「绑定」或「版本」历史中选择任意当前版或已归档发行版，通过批量修改接口 `changes.protocol` + `changes.protocolRelease` 显式升级或回退模型，按模型版本和能力/价格合同整批校验提交。
- 任务入队继续沿用宿主的 `ProtocolBindingJSON` 快照锁版：已入队或失败待恢复任务始终按原版本摘要查询和恢复，不受后续发版或模型切版影响。
